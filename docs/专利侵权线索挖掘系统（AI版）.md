

> 版本：V1.0  
> 面向阶段：MVP / 第一版产品落地  
> 核心目标：用户输入中文专利公开号，系统自动围绕权利要求1挖掘可能落入其技术特征范围的竞品，并输出 Top5 候选竞品的详细权利特征对比报告。

---

## 1. 产品背景

在专利侵权线索挖掘场景中，传统方式通常依赖人工检索专利文本、拆解权利要求、搜索竞品资料、阅读公开证据、制作权利要求对比表。该流程存在以下问题：

1. 检索范围大，人工容易遗漏竞品；
2. 专利语言与产品宣传语言差异较大，关键词搜索容易漏召回；
3. 公开资料来源分散，包括官网、新闻稿、PDF、产品手册、行业文章、专利文献、论坛、展会资料等；
4. 技术特征比对需要较强推理能力，普通搜索无法直接完成；
5. 侵权线索判断必须具备证据链，不能只依赖模型推测。

因此，本系统拟通过 **GPT-5.5 + 多搜索 Agent + 多搜索 API + 统一证据复核机制**，辅助完成中文专利的竞品侵权线索挖掘。

---

## 2. 产品目标

### 2.1 核心目标

用户输入一个中文专利公开号后，系统自动完成：

1. 获取并解析专利文本；
2. 抽取并拆解权利要求1；
3. 生成面向竞品挖掘的统一任务包；
4. 调度 GLM、Kimi、DeepSeek 三个搜索 Agent 并行检索；
5. 每个 Agent 独立发现候选竞品、检索证据、初步打分，并输出 Top5；
6. 系统汇总最多 15 个候选竞品，去重归并；
7. GPT-5.5 对候选竞品进行最终复核、补搜、统一打分；
8. 输出最终 Top5 详细报告，包括权利特征对比表、证据来源、分数、风险等级和人工复核建议。

### 2.2 非目标

MVP 阶段暂不承诺：

1. 给出正式法律侵权结论；
2. 替代律师、专利代理师或司法鉴定；
3. 保证找到所有真实侵权产品；
4. 自动处理所有从属权利要求；
5. 自动完成专利稳定性分析、无效检索或 FTO 分析；
6. 直接调用非公开数据库或付费商业数据库，除非后续接入。

系统定位为：

> 专利竞品侵权线索挖掘与证据整理辅助工具。

## 3. 目标用户

### 3.1 主要用户

1. 企业知识产权人员；
2. 专利工程师；
3. 研发部门专利分析人员；
4. 技术情报分析人员；
5. 竞品分析人员；
6. 专利代理师 / 律师的辅助研究团队。

### 3.2 用户核心诉求

用户希望：

1. 输入专利号后，快速得到可能相关的竞品；
2. 不仅看到竞品名称，还要看到公开证据；
3. 看到竞品与权利要求1的逐项技术特征对比；
4. 明确哪些特征有证据支撑，哪些只是推理，哪些证据不足；
5. 得到一个可继续人工核查的候选清单和报告。

## 6. 模型与 Agent 设计

### 6.1 模型分工

| 角色 | 模型 | 任务 |
|---|---|---|
| 专利解析与任务规划 | GPT-5.5 | 解析专利、拆解权利要求1、生成任务包 |
| 搜索 Agent 1 | GLM | 语义扩展视角发现竞品 |
| 搜索 Agent 2 | Kimi | 官方/长文资料视角发现竞品 |
| 搜索 Agent 3 | DeepSeek | 中文公开资料视角发现竞品 |
| 最终复核与报告 | GPT-5.5 | 去重、补搜、统一打分、生成报告 |

### 6.2 三个搜索 Agent 的共同职责

每个 Agent 都必须完整执行以下闭环：

```text
找竞品
→ 建立竞品池
→ 对候选竞品检索证据
→ 按权利要求1逐项匹配
→ 应用硬性规则
→ 按统一规则打分
→ 输出 Top5 JSON
```

三个 Agent 不是纵向分工，而是横向并行分工。

错误理解：

```text
DeepSeek 只找竞品
Kimi 只找证据
GLM 只做语义扩展
```

正确理解：

```text
DeepSeek / Kimi / GLM 都完整执行竞品发现、证据检索、特征匹配和打分。
区别只在于候选竞品发现阶段的搜索视角不同。
```

### 6.3 三个搜索 Agent 的差异化视角

| Agent | 候选发现视角 | 说明 |
|---|---|---|
| DeepSeek Agent | 中文公开资料视角 | 从中文网页、新闻、行业文章、企业资料、产品介绍中发现候选竞品 |
| Kimi Agent | 官方/长文资料视角 | 从官网、PDF、产品手册、白皮书、新闻稿、长文技术资料中发现候选竞品 |
| GLM Agent | 语义扩展视角 | 从同义表达、英文术语、技术方案变体、相似结构中发现候选竞品 |

### 6.4 候选发现与证据检索的区别

系统采用两阶段机制：

```text
阶段一：候选竞品发现差异化
阶段二：证据检索全量化
```

即：

1. 三个 Agent 在发现候选竞品时使用不同搜索视角；
2. 一旦形成候选竞品池，所有 Agent 都调用共享证据检索工具池，尽可能补全证据；
3. 证据检索不做偏好限制，目标是范围越广越好。

## 8. 单个搜索 Agent 工作流

### 8.1 总体流程

```text
S0 接收任务包
↓
S1 基于自身视角生成候选竞品发现 Query
↓
S2 使用主搜索源广泛搜索候选竞品
↓
S3 建立粗候选池
↓
S4 初筛候选池，去除明显无关项
↓
S5 保留重点候选，例如 8~12 个
↓
S6 对重点候选调用共享证据检索工具池
↓
S7 将证据绑定到 F1/F2/F3...
↓
S8 按硬性规则过滤
↓
S9 按极简计分规则打分排序
↓
S10 输出 Top5 JSON
```

### 8.2 候选池数量建议

| 阶段 | 建议数量 |
|---|---:|
| 粗候选池 | 15~30 个 |
| 初筛后重点候选 | 8~12 个 |
| 最终输出 | Top5，不足 5 个可少于 5 个 |

### 8.3 停止条件

单个 Agent 满足以下条件之一即可停止：

1. 已输出 5 个合格候选；
2. 搜索预算耗尽；
3. 连续多轮搜索没有新增有效候选；
4. 重点候选已完成证据检索和初步打分；
5. 没有足够高质量候选时，允许少于 5 个输出。

## 9. 硬性规则

硬性规则优先于打分规则。

### 9.1 排除规则

以下候选不得进入 Agent Top5：

1. 专利权人、申请人、发明厂商及其明显关联主体的产品；
2. 没有明确公司 / 品牌的候选；
3. 没有明确产品名、型号或产品系列的候选；
4. 没有任何公开证据 URL 的候选；
5. 权利要求1中任一必要技术特征明确不满足的候选；（这里需要注意：因为证据比对发生在竞品发现之后，如果证据比对后，发现所有竞品都明确不满足，那么需要重新搜索竞品）
6. 明显与专利技术方案无关的候选；
7. 模型虚构、无法验证或来源不存在的候选。

### 9.2 重要判断原则

1. 没找到证据 ≠ 明确不满足；
2. 证据不足只能判为“证据不足”，不能直接排除；
3. 只有存在公开反证，或产品结构/原理与权利特征冲突，才可判为“明确不满足”；
4. 不允许为了凑满 Top5 而虚构竞品；
5. 不允许虚构证据、标题、URL 或产品参数。

## 10. 单个 Agent 简易计分规则

### 10.1 技术特征判断档位

每个候选竞品针对权利要求1的每一条技术特征，分为四档：

| 判断档位 | 分数 | 定义 |
|---|---:|---|
| 明确满足 | 1.0 | 有公开资料直接指向该技术特征 |
| 可能满足 | 0.8 | 没有直接公开证据，但可以由公开资料中的产品结构、参数、工作原理、行业常识形成较强推理 |
| 证据不足 | 0.3 | 公开资料未能支撑判断，或只存在弱线索，无法可靠推理 |
| 明确不满足 | 排除 | 有公开反证，或产品结构/原理与权利特征冲突 |

### 10.2 “可能满足”的约束

“可能满足”必须给出推理链，不能只写“模型认为可能”。

可接受示例：

```text
公开资料显示该产品采用长条形方壳电芯，并用于 CTP 电池包结构；虽然资料未直接描述限位结构，但结合电芯布置方式和电池包装配要求，该特征可能满足。
```

不可接受示例：

```text
该产品也是电池包，所以可能有该结构。
```

后者只能判为“证据不足”。

### 10.3 候选总分

假设权利要求1拆解为 N 条技术特征：

```text
F1, F2, F3, ... Fn
```

候选竞品总分：

```text
候选得分 = 各技术特征得分之和 / 技术特征总数 × 100
```

如果任一必要技术特征被判定为“明确不满足”，该候选直接排除，不参与 Top5 排序。

### 10.4 同分排序规则

如果多个候选得分相同，按以下优先级排序：

1. 官方证据更多者优先；
2. 产品型号更明确者优先；
3. 证据覆盖的技术特征更多者优先；
4. 多个搜索源均找到的候选优先；
5. 证据来源可靠性更高者优先。

证据来源优先级：

```text
官网 / 官方 PDF / 产品手册
> 专利文献 / 标准 / 认证资料 / 年报 / 招股书
> 权威媒体 / 行业报告 / 研究机构报告
> 普通新闻 / 展会报道
> 自媒体 / 论坛 / 二手转载
```

## 11. GPT-5.5 最终复核规则

### 11.1 输入

GPT-5.5 最终复核模块接收：

1. 专利权利要求1原文；
2. 权利特征拆解表；
3. 三个 Agent 的 Top5 输出；
4. 合并后的候选池 JSON；
5. 所有证据 URL、摘要和来源类型。

### 11.2 复核任务

GPT-5.5 需要完成：

1. 合并同一竞品的不同名称；
2. 汇总同一竞品的所有证据；
3. 检查证据是否真实支撑对应权利特征；
4. 检查是否存在明确不满足项；
5. 对证据不足但排名靠前的候选进行补搜；
6. 对所有候选重新统一打分；
7. 输出最终 Top5；
8. 输出被排除候选及排除原因；
9. 输出证据不足但值得人工复查的候选。

### 11.3 GPT-5.5 可调用搜索引擎

GPT-5.5 在最终复核阶段可以调用：

1. Bocha；
2. Exa；
3. Brave；
4. Tavily；
5. Jina。

补搜触发条件：

1. 某候选排名靠前，但关键特征证据不足；
2. 某候选证据来源较弱，需要找官方证据；
3. 多个 Agent 提到同一候选，但证据不完整；
4. 疑似存在明确不满足项，需要查找反证；
5. 产品名称、型号或公司归属不清楚；
6. 需要查找产品手册、PDF、结构图、拆解资料或规格书。

## 15. 风险等级建议

最终报告中可根据分数给出风险等级：

| 最终分数 | 风险等级 | 说明 |
|---:|---|---|
| ≥ 85 | 高度疑似落入 | 多数特征明确满足或可能满足，证据较充分 |
| 70~84 | 中度疑似 | 多项特征具备支持，但仍有明显证据缺口 |
| 50~69 | 局部相似 | 部分特征相关，但完整落入证据不足 |
| < 50 | 弱相关 | 仅少数特征相关，暂不作为重点候选 |

若存在任一必要技术特征明确不满足，则无论分数如何，均不得评为“高度疑似落入”。

## 16. 功能需求

### 16.1 输入专利公开号

用户可以输入中文专利公开号，例如：

```text
CN107423660B
```

系统需要校验：

1. 格式是否可能为专利号；
2. 是否能找到专利文本；
3. 是否能抽取权利要求1。

### 16.2 权利要求1拆解

系统需要输出：

1. 权利要求1原文；
2. 拆解后的 F1/F2/F3；
3. 每个技术特征的工程术语；
4. 每个特征是否为必要技术特征。

### 16.3 多 Agent 并行检索

系统需要：

1. 同时启动三个搜索 Agent；
2. 每个 Agent 使用自己的候选发现视角；
3. 每个 Agent 维护自己的竞品池；
4. 每个 Agent 调用共享证据检索工具池补证据；
5. 每个 Agent 输出 Top5。

### 16.4 候选去重归并

系统需要合并：

1. 同一公司不同名称；
2. 同一产品不同型号写法；
3. 中文名/英文名/简称；
4. 同一 URL 或同一来源证据；
5. 多 Agent 对同一候选的不同判断。

### 16.5 GPT-5.5 最终复核

系统需要：

1. 对候选池逐项复核；
2. 检查证据是否支撑特征；
3. 需要时调用搜索引擎补搜；
4. 按统一规则重新打分；
5. 输出最终 Top5。

### 16.6 报告生成

系统需要至少支持 Markdown 报告。后续可支持 HTML、PDF、Word。

## 20. 主要风险与应对

### 20.1 搜索遗漏

风险：公开资料分散，单个搜索 API 可能漏召回。

应对：

1. 三 Agent 差异化发现候选；
2. 证据阶段共享全量工具池；
3. GPT-5.5 最终可补搜。

### 20.2 模型过度推理

风险：模型将弱线索判为“可能满足”。

应对：

1. “可能满足”必须输出推理链；
2. 无推理链只能判为“证据不足”；
3. GPT-5.5 最终复核。

### 20.3 证据不可访问

风险：搜索结果 URL 失效或正文抽取失败。

应对：

1. 记录 URL 状态；
2. 尝试 Jina / Tavily / Exa Contents 多工具读取；
3. 无法读取的证据降权或排除。

### 20.4 竞品归并错误

风险：同一产品不同名称未合并，或不同产品被错误合并。

应对：

1. 使用公司名、产品名、型号、别名、URL、技术描述综合去重；
2. GPT-5.5 最终复核归并结果。

### 20.5 法律结论风险

风险：用户误将系统输出当成法律结论。

应对：

报告中明确声明：

```text
本报告仅基于公开资料进行专利侵权线索辅助分析，不构成法律意见或正式侵权结论。
```

## 22. 最终方案摘要

本系统采用 **GPT-5.5 主控 + 三搜索 Agent 并行 + 多搜索 API + 统一证据复核** 的架构。用户输入中文专利公开号后，由 GPT-5.5 解析并拆解权利要求1，生成统一任务包。GLM、Kimi、DeepSeek 三个搜索 Agent 分别从语义扩展、官方/长文资料、中文公开资料三个视角发现候选竞品。每个 Agent 均独立完成候选发现、证据检索、特征匹配、硬性规则过滤和初步打分，并输出 Top5。证据检索阶段不做偏好限制，所有 Agent 均调用共享全量证据检索工具池，尽可能补全公开资料。系统将最多 15 个候选竞品去重归并后，交由 GPT-5.5 最终复核、必要补搜、统一打分，并输出最终 Top5 权利特征对比报告。

核心判断规则为：

```text
明确满足 = 1.0
可能满足 = 0.8
证据不足 = 0.3
明确不满足 = 排除
```

该系统不直接输出法律侵权结论，而是输出可追溯、可复核的专利竞品侵权线索分析报告。
